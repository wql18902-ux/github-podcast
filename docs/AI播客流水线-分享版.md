# AI 播客流水线：给自己定制一期「听得进去」的 AI 内容

> 一套从 GitHub 抓开源项目 → 逐文件读源码 → 写成口语稿 → 合成音频 → 跑步时听的自动流水线。
> 核心不是「做一个播客」，是**用最省力的时间，把最相关的一手知识，装进正在做的事里**。

---

## 一、这套东西解决什么问题

想持续学 AI，但遇到三个卡点：

- **现成内容太浅**：AI 博主讲的多是基础操作，没有增量；长视频看着累、信息密度低。
- **没时间专门学**：每天工作已经很满，单独腾时间学 AI 不现实。
- **学了不落地**：听完就忘，跟自己做的事接不上。

于是换一个思路：**不找内容，自己生产内容**——让 AI 每天替我拆一个高价值开源项目，写成正好能在我本来就要花的时间里（跑步、通勤）听完的一期音频，而且每一项都能对回我正在做的事。

---

## 二、整体思路：三个支柱

| 支柱 | 做法 | 解决什么 |
|---|---|---|
| **深度** | 开源项目不只看介绍，直接 clone 到本地，逐文件读源码 | 别人讲得浅，我要源码级的架构和细节 |
| **定制** | 结合我的信息源 + 我的工作区，只讲对我有用的 | 大众教程是给大众的，不适合我 |
| **闭环** | 每期结尾落到「我能用来干什么」，听完直接接行动 | 学习不能停在「听过」 |

---

## 三、流水线四环

```
① 信息源   抓当日海外高赞 AI 项目（按主线分类、去掉搬运）
② 拆解     选定项目 → clone 到本地 → 逐文件读源码 → 结构化拆解笔记
③ 播客     拆解笔记 → 口语稿 → 合成音频
④ 落地     抽出「我能用来干什么」→ 推送提醒 → 回来决策
```

### ① 信息源

- 从 GitHub 抓**海外高赞 AI 开源项目**（去中文、去搬运号）。
- 筛选中：星数门槛 + 近 90 天有更新（保证时效）+ 没讲过（防重复）。
- 按**三条 AI 主线**分类：图像/视频生成、语音、Agent/LLM。

### ② 拆解（灵魂所在）

这是整套东西里最值钱的一步。对每个项目：

> **不上网看介绍，直接 clone 到本地，派 agent 把每份文件读一遍。**

要读到的东西：
- 核心架构、文件结构
- 每个文件的功能、文件彼此的关系
- 这套逻辑体现出的 **AI 范式**（这条是最高层的「灵魂」）

产出是一份**结构化拆解笔记**，字段固定：

1. 一句话定义　2. 作者 + 思路来源　3. 输入→输出　4. 信息流
5. 文件地图（含文件职责和调用关系）　6. 文件亮点
7. 跟默认做法的差异　8. 做得好的 / 不够的　9. AI 范式提炼
10. 跟我对接（落地三问）　11. 信息截止　12. 当前版本

### ③ 播客（口语稿的固定骨架）

拆解笔记转成口语稿，七段：

1. **开场钩子**——一句反常识或悬念，开头 100 字内进正题
2. **这项目是什么 + 为什么值得你听**
3. **拆解主体**——输入输出 → 信息流 → 文件地图 → 文件亮点
4. **思维的分野**——跟同类比，好在哪、不够在哪
5. **AI 范式**——最高层，一段讲透
6. **回到你身上**——这项目我能用来干什么、要不要装、还是只借鉴思路
7. **一句话带走**——一条判断标准

### ④ 落地

第 6 段「回到你身上」抽出三个问题，每天推送提醒：
1. 这项目跟我哪条主线 / 哪个板块相关？
2. 它的核心思路，能补我一个「今天就能改」的细节吗？
3. 值不值得装 / 改，还是只借鉴思路？借鉴的话落到哪个板块？

听完之后的动作（人工）：
1. **聊透**——跑步中记的问题，回来跟 AI 对齐
2. **回看**——回到本地 clone 的源码，逐个问题核
3. **记笔记**——汇总成本项目的「学习文档」
4. **决定**——学到这就行 / 安排进工作区 / 改造它
5. **改造**——单独立项，仓库复制成参考

## 四、实际运行：每天全自动

| 时间 | 谁 | 干什么 |
|---|---|---|
| 22:30 | 定时任务（纯脚本） | 抓信息源 → 选料 → 逐文件读源码写稿 → 验收 |
| 02:00 | TTS 合成 | 读稿 → 语音合成 → 上传云盘 |
| 08:45 | 定时任务 | 抽「回到你身上/一句话带走」→ 推送提醒 |
| 每周日 21:00 | 定时任务 | 排下一周选题 |

早上打开云盘就能听，全程不用管。

---

## 五、验收：只拦真失败，不设目标值

自动化最怕「看起来跑完了，其实是糊弄的」。所以设了几道机械闸：

| 闸 | 判据 | 拦什么 |
|---|---|---|
| 稿子被更新 | 文件修改时间变新 | agent 没写 / 写了没落盘 |
| 不是空稿 | 正文汉字 ≥1500 | 写漏、写空 |
| 过程走了 | 拆解笔记字段齐全、体量够 | 跳过读源码、糊弄 |
| 时效 | 稿里写明「信息截止」 | 拿不准是不是当下有效的信息 |
| 防重复 | 本期项目没讲过 | 重讲旧项目 |
| 待消费 | 上一期稿子合成完了才写新的 | 覆盖掉还没合成的稿子 |

**核心口径：字数不设上下限。** 固定字数会把手段当目标，为凑时长拖语速、为凑字数注水。
**短不是失败，水才是。** 真正该看的是信息密度——讲得够不够具体。

---

## 六、一句话总结

> AI 播客不是「找内容听」，是「用最省力的时间，把最相关的一手知识，装进正在做的事里」。
>
> 三件事做到就算成——**逐文件读源码**（深度）、**跟自己的工作区强绑定**（定制）、**听完直接接落地**（闭环）。
>
> 这套流水线的价值，是把这三件事从「手动」变成「每天自动出一期、早上就能听」。
