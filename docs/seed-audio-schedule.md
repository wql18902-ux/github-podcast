# 豆包定时任务配置（套2：合成 + 上传网易云）

> 这是给豆包 App 定时任务用的触发指令。豆包每天定时触发，读本机产出的文稿，按 seed-audio-flow.md 合成，上传网易云。
> 流程本体见 `docs/seed-audio-flow.md`，这里只管「定时触发 + 读哪个文件 + 什么时候该跳过」。

## 时序（2026-09-14 改）

| 套 | 谁 | 时间 | 干什么 |
|---|---|---|---|
| 套1 | **WorkBuddy** 自动化「AI播客拆解写稿」（也支持手动 `bash scripts/daily-prepare.sh`） | 22:00 | fetch → 选料 → 拆解写稿（深度规范照 skill `podcast-depth-writing`）→ `scripts/verify-episode.sh` 验收 → 写状态 |
| 套2 | **豆包** App 定时任务「播客合成传网易云」——**就是本文这份指令** | 02:00 | 过两道闸 → 读 `latest-script.md` → seed-audio 合成 → 上传网易云 |

写稿可能跑 2-4 小时（clone 源码 + 拆最多 3 个项目 + 写长稿），22:00 起跑正好给豆包 02:00 留出窗口。

> ⚠️ **22:00 是个卡边的点**：若某夜写到 02:00 之后才落盘，豆包那班读到的就是旧稿，
> 闸 b（12 小时）会拦住，当夜没音频。再攒几期实测时长后，可考虑把写稿提到 21:00 或 21:30 更稳。


## 定时触发指令（复制进豆包定时任务）

```
每天凌晨 02:00 执行以下任务：

0. 先过两道闸。任一不过就立刻停，只输出一行原因，不要合成：

   a) 读 <项目根目录>/output/latest-status.txt
      - 文件不存在，或第一行不以 `OK` 开头
        → 停。输出：`跳过：套1 失败（<状态文件里的原因>），latest-script.md 是旧稿。`
        套1 失败时脚本不会覆盖 latest-script.md，合成了就是重播上一期。

   b) 检查稿件新不新（上一道闸挡不住「套1 整晚没跑」的情况）：
      在终端执行 find <项目根目录>/output/latest-script.md -mmin -720
      - 没有任何输出 → 稿件超过 12 小时没更新，是旧稿
        → 停。输出：`跳过：latest-script.md 超过 12 小时没更新，是旧稿。`

1. 读 <项目根目录>/output/latest-script.md（今天的口播稿）。

2. 合成必须用**豆包自带的 seed-audio 技能**（Seed Audio 1.0）：
   先 Read `<豆包 agent_mode 工作区>/.skills/seed-audio/SKILL.md`
   并按它的指引执行，走 **T2A 模式**调用 text_to_audio_plus，**不要绕过 skill 直接裸调工具**。
   流程本体见 <项目根目录>/docs/seed-audio-flow.md：
   切稿（用 `python3 scripts/split_segments.py output/latest-script.md 4.0 /tmp/segs`，不要手写内联脚本；
        PACE 4.0 = 每段目标 480 字 ≈ 120s，顶满单次生成 2 分钟上限，能放多少就放多少、段数更少、语速更快档）
   → 看报告里的「真实语速」（汉字/秒、字符/秒两口径）和 clip 告警（`[!] N 段撞 30-120s 边界被 clip` / `[✓] 无 clip`）；
     出现 clip 告警说明语速失真，按报告处理或记录说明
   → text_to_audio_plus 分批并行（固定主播前缀，每段带 duration）
   → 下载 wav → afinfo 验时长 → 提取 PCM 拼接
   → afconvert 压单声道 64kbps m4a
     （命名 output/audio/项目名-播客完整版-时长min.m4a，**时长取实测值，不取标称**，存到 audio 分类）

   固定主播前缀（逐字一致，所有段一字不差；音色为慵懒魅惑御姐 + 全片 BGM/音效/环境声打包）：
   一档单人科技播客，主播是慵懒魅惑的御姐女声（魔女 / 卡芙卡风格，带松弛勾人感）：30 岁女性声优，
   声线低沉磁性，轻微气泡颗粒感，慵懒松弛，尾音轻轻拖长，语气暧昧从容，呼吸感自然，情绪淡淡的，不夸张。
   安静室内底噪，微弱空气声。全片叠加极轻柔的氛围 BGM（舒缓、循环、低音量不压人声）与微弱环境音效，
   人声 + BGM + 音效 + 环境声整体打包合成。说：“（本段正文）”

3. 上传到网易云云盘（保持原文件名）：
   bash scripts/pipeline.sh upload output/audio/项目名-播客完整版-时长min.m4a

4. 汇报实测时长：
   `实测 X 分钟`（X = afinfo 实测总时长分钟数向下取整）。例：`agent 实测 57 分钟`。
```

## 衔接点

两个，两个都由套1 的脚本写、套2 只读：

- `output/latest-script.md` —— 稿件。套1 覆盖写，套2 只读，双方不猜路径。
- `output/latest-status.txt` —— 状态闸。格式：
  `OK 日期 项目名 | N汉字 | 拆解10字段 | 预估X分钟/1.5x听Y分钟`，失败则是 `FAILED 日期 原因`。
  **套1 无论成败都写**，套2 读到非 OK 就跳过。

## 语速定档（2026-09-11 改，重要澄清）

**产出侧 PACE 4.0**（`--unit char`）：单段目标 480 字 ≈ 120s，约 4 字符/秒 ≈ 187 汉字/分钟，**1.0x 直接可听**。
450–500 字/段是用户实测效果最好的档。

**1.5x 从来不是偏好**——是早期 PACE 3.58（~148 汉字/分钟）语速太慢，用户被迫开 1.5x 补偿
（148 × 1.5 = 222 汉字/分钟才落在标准播客区间）。PACE 4.0 定档并在他处实测确认后，
**1.5x 汇报已去除**，只报实测时长。

旧档 PACE 3.58（2026-09-10 按「固定 1.5x 听」反推定档）已作废，理由就是上面的澄清：
把补偿手段当成了偏好。

倍速收听会放大语气词密度、开头铺垫、同一观点重复——内容规则仍见
`scripts/write-episode-prompt.md` 的「按 1.5 倍速听来写」一节（内容规则与语速档无关，保留）。
