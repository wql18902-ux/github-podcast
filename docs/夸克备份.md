# 夸克备份（网易云挂了之后的第二落点）

> 2026-10-03 建。配套脚本 `scripts/upload-quark.sh`，二进制 `bin/kuake`（夸克网盘 CLI v1.5.0）。

## 为什么有这条链路

网易云云盘的 CLI 扫码登录 2026-10-01 过期，之后每晚后台重登都卡在「二维码已过期，请重新获取」，连挂三晚，成品音频只在本地没人听得到。现在每次上传都双写：

- `scripts/pipeline.sh upload` / `upload-local` 先传网易云，再往夸克传一份；
- 两块任意一块传上，这步就算成（网易云挂了夸克顶上）；
- 两块都没传上，退出码 1，且夸克侧会写日志 + 推飞书告警。

## 有哪些部件

| 部件 | 干什么 |
|---|---|
| `scripts/upload-quark.sh` | 上传入口，也是 Cookie 的唯一存取处 |
| `bin/kuake` | 官方 CLI（v1.5.0 darwin-amd64，已 gitignore；M4 走 Rosetta，实测正常） |
| `output/upload-quark.log` | 每次上传一行结果：`日期 时间 文件名 OK/FAIL` |
| macOS 钥匙串 | 存整段 Cookie；服务名写在 `scripts/upload-quark.sh` 顶部的 `KEYCHAIN_SERVICE`，不落任何文件 |
| `scripts/pipeline.sh` | `upload` / `upload-local` 两个上传点已接上双传 |
| `config/tools.json` | 外环工具表里的 `upload_quark`（失败只记日志不 abort） |

## Cookie 怎么配（唯一需要人肉的步骤）

1. 浏览器登录 `pan.quark.cn`；
2. F12 → Network → 点任一请求 → 复制请求头里**整段** Cookie（不是只复制 `__pus` 那一截）；
3. 跑 `bash scripts/upload-quark.sh --set-cookie`，粘贴，Ctrl-D 结束；
4. 脚本会顺手调 `kuake user` 验登录态，没过会明说「Cookie 可能不完整或已失效」。

换号或怀疑串号：`bash scripts/upload-quark.sh --delete-cookie` 删掉重配。

### 懒人办法：让 agent 代抓 Cookie（2026-10-03 实测可用）

不想手抄就让 agent 驱动浏览器：playwright（本机已装）开无头 Chromium 打开 `pan.quark.cn` → 截图二维码给用户 → 用户用夸克 APP 扫 → 轮询到 `__pus` cookie 后用 `context.cookies()` 抓全量（**含 HttpOnly，`document.cookie` 抓不到的那种**）→ 经 stdin 直接喂 `bash scripts/upload-quark.sh --set-cookie`。全程 Cookie 不打印、不落盘。2026-10-03 就是这么把 10-01/02/03 三期补传完的。要点：脚本放 `/tmp` 别进项目目录；只用 stdin 传递；跑完把 `/tmp` 里的临时脚本删掉。

## 日志在哪

`output/upload-quark.log`，长这样：

```
2026-10-03 22:35 template-播客完整版-58min.m4a FAIL
```

只有真跑了上传才有行；Cookie 没配（退出 2）不算上传尝试，不写行。

## 失效现象对照

| 看到的 | 含义 | 怎么办 |
|---|---|---|
| 退出 2：「未配置夸克 Cookie」 | 钥匙串里没有这条 | 跑 `--set-cookie` |
| 退出 1 + 日志 FAIL + 飞书「夸克上传失败」 | Cookie 失效 / 不完整 / 网盘满 | 重新 `--set-cookie`，不行就 `--delete-cookie` 再配 |
| kuake 输出 JSON 里 `"success": false` | 同上，具体原因在 JSON 的 `message` 字段 |
| 日志有 FAIL 但没收到飞书告警 | 告警通道本身坏了（lark-cli 缺 `im:message.send_as_user` scope） | 手动跑一次 `lark-cli auth login --scope "im:message.send_as_user"` 补授权 |

## 补历史三期（10-01 / 10-02 / 10-03）

配好 Cookie 后跑：

```bash
bash scripts/upload-quark.sh "output/audio/template-播客完整版-58min.m4a"   # 10-01
bash scripts/upload-quark.sh "output/audio/handoff-播客完整版-54min.m4a"    # 10-02
bash scripts/upload-quark.sh "output/audio/otlp-播客完整版-52min.m4a"       # 10-03
bin/kuake list "/" | grep -E "template|handoff|otlp"   # 三个文件名都应出现
```

传到的位置是夸克网盘 **`/播客备份/`** 目录（2026-10-03 应用户要求从根目录迁入；`upload-quark.sh` 默认落这个目录，文件夹不存在会自动创建）。

## bin/kuake 丢了怎么重下

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  curl -sL --http1.1 -o bin/kuake \
  "https://github.com/zhangjingwei/kuake_cli/releases/download/v1.5.0/kuake-v1.5.0-darwin-amd64"
chmod +x bin/kuake
bin/kuake -v    # 应回 kuake v1.5.0
```

注意两点：本机 7890 代理常死，`curl` 必须 `--http1.1` 且剥代理变量，否则会静默超时；文件大小应正好 **6850864 字节**，对不上就是下错了（别下成 `kuake-mcp` 那个，那是 MCP server）。

## 红线条目

- Cookie 只进 macOS 钥匙串，不写文件、不进日志、不进 git；
- 上传成功只认「kuake 退出码 0 且输出 JSON 含 `"success": true`」，不接受mock、不接受手写假 OK；
- 报错只提取 kuake 的 `message`/`error` 字段进日志和告警，绝不在任何输出里回显 Cookie。

## 夸克网盘整理（2026-10-03 应用户要求做了一次）

整理前的烂摊子：根目录平铺 49 个王振宇直播回放 mp3（树成林/浪前/志愿课/答疑室混在一起）＋ 3 个播客 m4a。

现在的结构（只 move 不删，移动清单在 `/tmp/quark-move-manifest.tsv`，重启前可据此还原）：

```
/播客备份/                        3 个播客 m4a（upload-quark.sh 默认落点）
/王振宇直播回放/
├── 树成林系列/                   17 个（树成林_ 前缀：赚钱系列/预习期/加餐）
├── 浪前正课/                     10 个（「DAY*」正课 + 开营仪式，含 2025 年重传的一份 DAY2）
├── 答疑室/                       8 个（浪前答疑室/历年答疑 vol.*，vol.001 有两份不同批次上传的）
├── 志愿课/                       6 个（「2024」树成林志愿课第 1/2/4/5/6/7 讲，第 3 讲没传过）
└── 其他单场/                     8 个（单词突围/S级策略/贸易战/跨年等单场直播）
```

分类是按文件名语义匹配的（一次性脚本，用完即弃）。已知一处疑似重复：`浪前正课` 里 2025 与 2026 两份「DAY2」大小同为 121.5MB，可能是同一场直播的两次上传——**没有动它们**，用户自己比对后再决定删不删。
