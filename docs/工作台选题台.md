# 工作台选题台

## 这是什么

这是本地播客选题台，地址固定：

```bash
python3 scripts/workbench_server.py
# http://127.0.0.1:8788/
```

它只绑定 `127.0.0.1`，不对局域网开放。页面是「左侧栏 + 主区」两栏：左侧栏放四个入口（带各区实时计数）和底部的飞书同步卡，主区跟着切换。

- 选题台：灵感收件箱、本周已选、排期中、已讲、不讲/归档。主区左边是灵感输入卡 + 分组列表，右边栏是 Claude 选题队列和选题分布。分组头可点击折叠/展开（「已讲」「不讲/归档」默认收起），左侧栏可整条收成 64px 图标栏。
- 候选池：`info_source.db.projects` 的简洁列表，配搜索和分类胶囊。候选名直接点开 GitHub 仓库；「加入选题」旁的详情按钮弹抽屉（细节 + 打开链接 + Claude 选题）。
- 已讲：期次页、拆解稿、成稿、音频。产物做成胶囊，音频带时长；有文稿没音频的标「待合成」；仓库名是可点的 pill（链接取自期次数据，缺省按 `owner/repo` 拼 GitHub）。
- 稿件索引：`output/` 下的 Markdown 索引，左列表 + 右阅读器。左列可收起让阅读器占满（外侧留固定展开钮）。

页面样式在 2026-09-15 按设计稿重做过一版（细线 + 毛玻璃），改前改后的四屏留档在 `docs/design/workbench-codex/`。三块面板（左侧栏、选题台分组、稿件索引左列）的折叠状态记在浏览器 `localStorage` 的 `wb.ui` 键里，清掉即回默认。

## 数据库

本地 `info_source.db` 是唯一真相源。`fetch.py` 的抓取规则和黑名单不改。

选题台新增的表：

- `selections`：选题记录。
- `selection_tasks`：Claude 选题任务。
- `feishu_sync_state`：飞书记录和同步状态。
- `script_pushes`：讲稿推送台账（一期一条，记 md5 与附件 file_token）。

选题状态固定为：

- `inbox`：灵感收件箱
- `candidate`：候选
- `shortlist`：已选
- `rejected`：不讲
- `scheduled`：排期中
- `used`：已讲
- `archived`：归档

页面和飞书都不提供硬删除，只能归档。

## WorkBuddy 推送入口

WorkBuddy 以后不要直接只发群消息，统一写本地库并同步飞书：

```bash
python3 scripts/selection_push.py --title "灵感标题" --summary "一句话说明" --url "https://example.com"
```

也可以传 JSON：

```bash
echo '{"title":"灵感标题","summary":"一句话说明"}' | python3 scripts/selection_push.py
```

这个入口默认来源是 `WorkBuddy`，先写 `info_source.db`，再同步飞书。如果不希望立即同步，加 `--no-sync`。

## 本地服务

服务已注册成 launchd 常驻进程：

```bash
launchctl kickstart -k "gui/$(id -u)/com.github-podcast.workbench"
launchctl print "gui/$(id -u)/com.github-podcast.workbench"
```

日志在 `/tmp/github-podcast-workbench.log` 和 `/tmp/github-podcast-workbench.err.log`。

## 本地 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/overview` | 一次取候选、选题、任务、稿件、期次和飞书状态 |
| POST | `/api/selections` | 新增灵感或项目选题 |
| PATCH | `/api/selections/{id}` | 改标题、说明、链接、为什么值得讲、状态、优先级、排期日期 |
| POST | `/api/selections/{id}/claude` | 创建 Claude 选题任务 |
| POST | `/api/selections/{id}/postpone` | 挪期：`next_week`=顺延 7 天并置排期，`back`=撤回已选清日期 |
| GET | `/api/tasks/{id}` | 查任务状态和人话版报告 |
| POST | `/api/weekly-tasks` | 周选题入队（同周已有排队/执行中的计划则幂等复用） |
| GET | `/api/weekly-tasks/{id}` | 查周任务状态 |
| GET | `/api/weekly-plans` | 最近 5 份周计划（含任务状态） |
| POST | `/api/weekly-plans/{id}/confirm` | 确认落库（`adopt: {日期: 是否采纳}`），成功后自动回写选题库第 4 块 |
| POST | `/api/feishu/sync` | 立即同步飞书 |
| POST | `/api/feishu/push-script` | 推讲稿：body 可带 `{"date": "YYYY-MM-DD"}`，不带就取最新一期。等价于 `feishu_sync.py --push-script --force` |

写接口只允许本机访问；服务本身也只绑定 `127.0.0.1`。

## Claude 选题按钮

每条选题和候选都可以点「Claude 选题」。确认框会写清：

- 要分析哪个选题。
- Claude 会检查什么。
- 只做选题分析，不写稿、不改文件、不触发合成。

后台有**两条互不挤占的 Claude 队列**：单条选题分析一条（15 分钟超时）、周选题一条（30 分钟超时），最多两个 claude 并发。命令使用：

```bash
claude -p "<prompt>" --permission-mode plan --output-format json --disallowedTools Bash,Edit,Write,MultiEdit,NotebookEdit
```

结果保存到 SQLite，同时写 `output/selection-tasks/task-<id>.md` 和 `task-<id>.log`。失败原因也会显示在页面，不静默。

## 周选题（2026-09-16 起）

选题台右栏「周选题」卡 → 确认弹窗 → Claude 排下周 7 天（材料全内联：选题库 0-3 块、防重复台账、三池选题、候选池 stars 前 40、已占用日期；明写不检索文件）→ 跑完弹 7 天建议面板（勾选框默认全选 + 理由 + confidence）→「确认排期」落库。

- 排期真相源是 SQLite（`selections.scheduled_for`），确认后**自动回写 `选题库.md` 第 4 块**作镜像（整块重生成、临时文件+原子替换）；回写启用前的原稿在 `_归档/选题库-镜像回写前快照-20260916.md`。
- 选题台「排期中」组按日期排序，行上有日期徽章和「挪到下周」「回已选」快捷钮。
- cron：`scripts/weekly_enqueue.sh`（**2026-09-21 实测由 WorkBuddy 自动化「选题库周排期」每周日 05:00 调用**，旧文写「Trae 周日 21:00」未核实；Trae 侧若还留着一份会是同一天跑两遍）只负责入队，**确认保留人工**；服务没起写 `output/selection-tasks/weekly-enqueue.log` 并非 0 退出，不静默。
- 校验不过就判失败：7 天必须连续且等于下周、拼盘拆开对防重复台账，违反原因写进报告不静默。

### 无头排期（2026-09-20 定：定时任务 / agent 走这条）

「确认保留人工」说的是**页面上不自动落库**；定时任务或 agent 可以走 API 自己落，顺序固定四步：

1. **先退役已交付的排期行**：`update selections set status='used' where id in (…)`。
   漏了这步，回写会把上周的日期一起列进第 4 块——回写列的是**所有** `status='scheduled'` 的行，不看日期。
2. **直接往 `weekly_plans` 插一行**：字段是 `(week_start, status, result_json, created_at)`，
   **没有 `prompt` 列**（prompt 在 `weekly_tasks`）。照 `create_weekly_plan()` 的签名写会报
   `table weekly_plans has no column named prompt`。
   `result_json` = `{"days":[{"date","title","project","reason"}, …]}`，没项目的那天 `project` 留空 → 落成 `kind='idea'`。
3. `POST /api/weekly-plans/<id>/confirm`，body `{"adopt":{"YYYY-MM-DD":true, …}}` → 落库并自动回写第 4 块。
4. 列头也是 `rebuild_topic_library_schedule()` 写的：**改列头 = 改 `workbench_server.py` 里那一行 + 重启服务**。
   只改文件不重启，服务进程里还是旧代码，下次点确认会把列头刷回旧版。

三个坑：

- **别用 `POST /api/weekly-tasks` 造计划**：它会连带建一条排队的 `weekly_tasks`，服务里的 claude 线程
  可能直接认领去跑 Claude，不是你要的。造计划就自己插 `weekly_plans`。
- `confirm_weekly_plan` 的 `project` **只认第一个含 `/` 的分词**（按 `[+、,，\s]+` 切）。所以拼盘
  **只能登记一家**，另一家写进 `reason`——它会进第 4 块「预选」列，夜班 agent 看得到。
- 第 4 块列头 2026-09-20 起是 `日期 | 主题 | 预选`（原为 `日期 | 选题 | 标的 / 说明`）。

## 飞书多维表格

第一次创建/接线：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY python3 scripts/feishu_sync.py --setup
```

以后手动同步：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY python3 scripts/feishu_sync.py --once
```

服务启动后每 5 分钟自动同步一次；侧栏底部同步卡里也有「立即同步」和刷新。

配置在 `config/selection-sync.json`，只放 Base token、表 ID、表名、视图和字段名，不放密钥。

飞书表字段：

- 标题
- 类型：灵感 / GitHub 项目
- 项目名
- 链接
- 一句话说明
- 为什么值得讲
- 状态
- 优先级
- 来源
- 本地ID
- 更新时间
- 稿子：**附件字段**，挂这一期的讲稿 md（见下节）

预设视图：

- 灵感收件箱
- 本周候选
- 已讲
- 归档

## 同步规则

- 本地 SQLite 是唯一真相源。
- 飞书新增会先写进 SQLite，成功后才生效。
- 本地新增和修改会推到飞书。
- 两端同时修改时保留本地版本，飞书状态改成「冲突」，不自动覆盖。
- 飞书记录不硬删，只同步归档状态。

## 讲稿进飞书（2026-09-16 加）

同步按钮只同步**选题字段**，不碰稿子——讲稿走单独一条通道：把这一期的
`output/<日期>-script.md` 作为附件，挂到选题表里 `scheduled_for` 等于该日期那条记录的
「稿子」字段上。字段不存在时自动用 `+field-create` 建（type=attachment）。

两条触发路径：

- **过闸自动推**：`scripts/verify-episode.sh` 验收通过后调
  `feishu_sync.py --push-script --date $TODAY`，日志落 `output/feishu-push.log`。
  推送失败**不影响验收结果**，也不写进 `latest-status.txt`（02:00 合成班读的是它首行 OK 的契约）。
- **页面手动推**：侧栏飞书同步卡上的「推讲稿到飞书」，走
  `POST /api/feishu/push-script`，内部 `force=True`（稿子没变也重推一遍）。

幂等与「不堆积」：

- 取稿子看 `output/` 下**带日期**的 `*-script.md`，**不读 `latest-script.md`**——那是当期滚动指针，夜班一跑就滚。
- 台账 `script_pushes` 存 md5：稿子没变且非 force 直接跳过（自动推通常走这条）。
- lark 的 `+record-upload-attachment` 是**追加**语义，所以每次上传前先按台账里的
  `file_token` 删掉旧附件，再兜底读一遍单元格、把同名的也删掉。换稿子只留一份。

## 拆解稿显示

新拆解稿必须把 `## 人话导览` 放在技术细节前。工作台渲染时优先显示这一节，技术拆解原文折叠到后面。

## 期次产物声明（2026-09-16 起）

**新期次接线只写 page.md，不改 `workbench_server.py`。** 在 `output/episodes/ep<N>-<slug>/page.md` 的开头声明块里写机器可读行：

```markdown
- repo: owner/repo            （一期多仓就写多行；容忍反引号或完整 GitHub URL）
- 稿子：`output/2026-09-16-script.md`
- 拆解笔记：`output/2026-09-16-breakdown.md`
- 音频：`output/audio/xxx-播客完整版-46min.m4a`   （还没合成就写「待合成」，不挂产物）
```

`collect_episodes` 按三级优先取数：**page.md 声明 > `EPISODE_REPOS`/`EPISODE_ARTIFACTS` 字典 > 按「上线」日期猜 `output/<日期>-*.md`**（日期启发只对字典不认识的新期次生效）。

解析容错（写声明行时不用管，但别写歧义格式）：

- 行内的 `latest-script.md` 这类滚动指针会跳过，取行里写着日期的归档件。
- 值里带「已丢失」的行不解析（ep5 拆解笔记那行是叙述，不是可用产物）。
- 声明的路径不存在时自动让位给字典/启发式，不会挂出死链。

## 性能原则（2026-09-16 定，改版别加回来）

- **持久卡片不用 `backdrop-filter`**：卡片叠在近纯色底上，把不透明度提到 .85 视觉几乎一样，但滚动/重绘省掉逐帧重采样。毛玻璃只留三处——sidebar、抽屉 `drawer-body`、弹窗 `modal-card`（单实例、瞬态、不滚动）。
- **`render()` 只重建当前 tab**：全量重建 5 个 tab 会重置正在播放的 audio，也让每次操作整页重绘。侧栏计数、页头照旧全量更新。
- **`docViewer` 不随索引刷新重建**：`renderDocs` 只重写 `#docsLeft`；同一篇稿子用 `state.docPaintedPath` 防重画——watchTask 轮询完成 → load() → render() 这条链不会打断播放。
- **灵感输入草稿重建后回填**：renderSelection 重建前暂存 FormData + 光标位置。
- 折叠态（侧栏/分组/左列）减少首屏 DOM；折叠的分组只渲染组头。

## 排障

1. 页面打不开：确认命令在项目根目录跑，且端口没有被别的程序占用。
2. Claude 任务一直排队：看 `output/selection-tasks/` 最新日志；单条分析和周选题各有一条队列，互不挤占。
3. Claude 任务失败：页面详情里会显示失败原因；找不到 CLI 时检查 `claude` 是否安装，或用环境变量 `CLAUDE_BIN` 指定路径。
4. 飞书同步失败：先看 `http://127.0.0.1:8788/api/overview` 里的 `feishu.last_sync`，再跑 `--once`。项目里有死代理坑，CLI 已自动剔除代理变量。
5. 讲稿没推到飞书 / 推歪了：先看 `output/feishu-push.log`（每次带时间戳，日志里就是 `push_script` 的 JSON，含 `reason`）；再核对台账 `select * from script_pushes`。三种常见原因——当天没有 `scheduled_for` 等于该日期的选题、那条选题还没有 `lark_record_id`（先跑一次同步）、稿子文件不在 `output/`。**上传路径必须是相对项目根的相对路径**，lark-cli 拒收绝对路径（err: unsafe file path）。
6. 飞书没配置：重新跑 `--setup`；不要把 API Key 写进配置或文档。

## 红线

- 不硬删选题、任务、飞书记录或项目文件。（讲稿推送会删**旧附件**——同一格里换稿只留一份，
  这不算「硬删飞书记录」，是附件单元格的替换，见上节。）
- 不改 `fetch.py` 的 `QUERIES` 和 `KNOWN_CN_ORGS`。
- 不改 `output/episodes.log` 历史记录。
- 不把飞书 token、API Key 写进代码、日志或 Markdown。
- Claude 只做选题分析，不自动写稿、不自动改文件、不自动合成。
