# AI 播客思路：从王振宇的起源到我的 github-podcast

> 这份文档做两件事：
> ① 把王振宇《绝对重要的时代里程碑》（2026.7.4 直播）里那套「AI 播客」思路提炼成骨架；
> ② 把我自己的 `github-podcast` 流水线对着这个骨架摆一遍——哪些抄对了、哪些是本地化的。
> 用途：分享 / 自查。发现我这条流水线跟原思路哪里走样了，对着改。

---

## 一、王振宇原思路：核心就一句话

> **「人们开始有了低成本为自己定义娱乐消费内容的机会。」**

他做成的东西表面是「一个播客」，本质是：

> **把「跑步没东西听」这个负担，改造成「零成本白嫖顶级 AI 学习」的复利资产。**

三根支柱：

| 支柱 | 原话 / 动作 | 解决什么 |
|---|---|---|
| **深度** | 项目不上网看，**clone 到本地、派 agent 把每份文件读一遍** | 别人讲得浅，我要源码级的东西 |
| **定制** | 结合**我自己的信息源 + 工作区**，只讲对我有用的 | 大众教程是给大众的，不适合我 |
| **闭环** | 听完回来走**五步**，落到我正在干的活上 | 学习不能停在「听过」 |

## 二、原思路拆成可复制的五个部件

### 部件 1 · 信息源：不是随便抓，是「跟我强相关」的筛选器

他手上先有一个 **GitHub 每日开源项目推荐**系统：按自己的业务板块 + trending 排序 + 经典程度，每天推一个高质量海外开源项目，还生成一份报告。

**关键**：筛的是「海外 + 高赞 + 跟我的板块相关」，不是「今天 GitHub 热榜」。这条决定了后面所有内容的品味。

### 部件 2 · 拆解：逐文件读源码（灵魂所在）

他对 AI 的原始指令（几乎是逐字）：

> 「每个开源项目不要上网看，**直接克隆到本地**，每天生成播客之前你自己派 agent **把每份文件全部读一遍**。
> 我要听到的是：这个项目的**核心架构、文件结构、每个文件的功能、每个文件彼此的关系**，以及它这个逻辑之下体现出来的 **AI 范式的思想转移**。
> 除了项目本身的精髓……怎么输入、怎么输出、信息怎么跑、流程怎么动、每个文件怎么设定、每个文件的亮点。」

**这就是「拆解」的模板。** 听到的不是营销介绍，是「文件之间怎么咬合」。

### 部件 3 · 播客：一期=一个项目的全解剖，结尾必须落到「你」

一期的固定内容：作者是谁 / 思路来源 / 好在哪 / 输入输出 / 信息流 / 文件架构 / 文件关系 / 跟竞品的思维差异 / 做得好与不好 / **最后一段：这项目你能用来干什么**。

最后这段是重点，他问的四个问题：
1. 要不要装？这个 skill / 命令要不要用？还是只借鉴思路？
2. 借鉴的话，跟你**已有的哪条思路**印证了？
3. 能补你**哪个细节**？
4. 哪个是**你今天就能落地**的？

> 注：他生成音频用的是 **MiniMax**（不是本地模型——本地 TTS 他试过两天，音色漂移、分段衔接差，放弃了）。

### 部件 4 · 落地五步（听完之后的动作）

1. **聊透**——跑步中记的问题，回来跟 AI 对 30-50 分钟
2. **回看**——回到本地 clone 的真身源码，逐个问题核
3. **记笔记**——汇总成本项目的「学习文档」
4. **决定**——学到这就行 / 安排进工作区 / 改造它
5. **改造**——单独立项，仓库复制成 reference

### 部件 5 · 沉淀：所有产出回到「一个工作区」

他从第一天建的就是 **Workstation（工作站）**，而不是一个个独立项目文件夹。
理由：记忆、资产、认知沉淀在**一个全局空间**里，AI 对你的理解不分拆、不断档——「越用越懂你」。
这是让前四个部件产生**复利**的地基。

### 顺带学到的两条「范式」（他反复炫耀的重点）

- **稳定 vs 智能释放**：机械底座用脚本 + 机械审核门锁死，只让大模型干「理解自然语言」这一件智能活。（来自 Artificial 画图项目）
- **视频是用来看的 → 是用来读的**：把画面压成机器好读的文本/JSON，绕开多模态。（来自 Video Use）

## 三、我的 github-podcast：对着骨架摆一遍

一句话自我定位（README 原话）：

> 从 GitHub 抓「海外高赞 AI 开源项目」，按**听众的三条 AI 主线**分类（写在 `config/audience.md`） → 每期选 1 个项目（撑不起就同主题拼盘，最多 3 个）→ **逐文件读源码**写口语化解读稿 → 豆包 seed-audio 合成 → 上传网易云云盘，在健身和无聊课上听懂 AI 的底层逻辑。

### 3.1 流水线四环（我的版本）

```
① 信息源     fetch.py          抓当日海外高赞 AI 项目
② 拆解       episode.py        选料 + clone 到本地 cache/
             + 夜班 agent       逐文件读源码 → 10 字段拆解笔记
③ 播客       夜班 agent        7 段结构口语稿 → 合成音频
④ 落地       提醒推送 + 五步    抽「落地三问」推飞书 → 回来决策
```

### 3.2 三根支柱，我各自落在哪

| 支柱 | 王振宇原版 | 我的落地 | 文件 |
|---|---|---|---|
| **深度** | clone 到本地逐文件读 | ✅ 一样。拆解笔记 **10 字段**（+2：信息截止/当前版本） | `output/<日期>-breakdown.md` |
| **定制** | 结合他自己的信息源 + 工作区 | ✅ 一样，但锚点换成了**我的四条**：三条 AI 主线 / 硬处境 / ai-brain 工作区 / 行动卡点 | `DESIGN.md` 第二节 |
| **闭环** | 落地五步 | ✅ 一样，但「最后一段」固定成**落地三问 + 一句话带走**，08:45 抽出来推飞书 | `个人启发/播客提醒.md` |

## 四、部件级对照（原版 → 我的）

### 4.1 信息源

| | 原版 | 我的 |
|---|---|---|
| 抓什么 | GitHub 每日开源推荐，跟业务板块相关 | `fetch.py` 抓海外（去中文 + `KNOWN_CN_ORGS` 黑名单）、stars≥3000、近 90 天有 push、未讲过 |
| 分类 | 按业务板块 | **三条 AI 主线**（见 4.5） |
| 暗线 | — | 「近 90 天有 push」保证**时效**；2026-09-11 又加了「信息截止/当前版本」两栏硬闸 |

### 4.2 拆解（灵魂，逐文件读源码）

| | 原版 | 我的 |
|---|---|---|
| 触发 | 「派 agent 把每份文件读一遍」 | 夜班 `claude -p` headless，任务书 `write-episode-prompt.md` |
| 产出 | 口播内容 | **拆解笔记 10 字段**（`breakdown.md`）+ **口播稿**（`script.md`），两个文件分离 |
| 灵魂字段 | 「文件关系 + AI 范式」 | 第 5 字段「文件地图」+ 第 9 字段「AI 范式提炼」 |
| 防糊弄 | — | **过程闸**：拆解笔记必须 ≥10 字段标题 + ≥2000 字节（这是「读没读源码」唯一能机械验的证据） |

**10 字段清单**（我的模板，`DESIGN.md` 第三节）：
1 一句话定义 · 2 作者+思路来源 · 3 输入→输出 · 4 信息流 · 5 文件地图 · 6 文件亮点 · 7 跟默认做法的差异 · 8 做得好的/不够的 · 9 AI 范式提炼 · 10 跟你对接 · 11 信息截止 · 12 当前版本

### 4.3 播客（稿子的 7 段骨架）

比原版多了一个固定骨架，`DESIGN.md` 第四节：

1. **开场钩子**（一句反常识/悬念，开头 100 字内进正题）
2. **这项目是什么 + 为什么值得你听**
3. **拆解主体**（输入输出 → 信息流 → 文件地图 → 文件亮点）
4. **思维的分野**（竞品差异 + 好/不好）
5. **AI 范式**（第 9 字段，灵魂，一段讲透）
6. **回到你身上**（落地三问）
7. **一句话带走**（一条判断标准）

> **跟我最像原版的地方**：就是第 6 段——「这项目你能用来干什么、要不要装、还是只借鉴思路」。
> **我比原版多做的**：把文风做了质检闸（反 AI 味、按 1.5x 倍速收听来写内容），原版没提这套。

### 4.4 落地闭环

| 原版五步 | 我的 |
|---|---|
| 1 聊透 | 跑步中记问题，回来跟 AI 对齐 |
| 2 回看 | 回 `cache/` 里的 clone 真身看源码 |
| 3 记笔记 | 拆解笔记 + 探讨结论 → 本项目的「学习文档」 |
| 4 决定 | 三选一：学到这就行 / 安排进工作区 / 改造它 |
| 5 改造 | 单独立项，仓库复制成 reference |

我的**自动化部分**：第 6 段「落地三问」由 Hermes 每天 08:45 抽成提醒卡，推「Hermes·灵感」群 + 归档 `个人启发/播客提醒.md`。
第 4-5 步（决定/改造）仍是**人工**，符合原版「这套要人来做」。

### 4.5 定制锚点（我的「适合你」= 四条）

原版是「跟我的工作区强绑定」，翻译成我的版本（`DESIGN.md` 第二节）：

1. **三条 AI 主线**（技术域）：AI 写真/漫剧、VoiceInk 语音、Agent 工作站 —— 每个项目先归到哪条线
2. **硬处境**（约束域）：16G M4 跑本地模型、减脂/OMAD、12 月四级、国央企就业 —— 「能不能落地」的现实约束
3. **ai-brain 工作区**（落地对象）：听完往哪个板块落，要具体到目录
4. **行动卡点**（行动域）：行动力差、完美主义拖延 —— 结尾给「今天能动手的最小一步」

> **红线**：原版逐字稿里裹着的「大众是垃圾」「得到必死」那类精英主义情绪，我**不要**。
> 只要「逐文件读源码」这套硬方法。要货、精准、别糊弄——跟他的方法合，跟他的情绪不合。

## 五、我的实际运行机制（2026-09-11 现状）

### 5.1 三个定时任务（时序）

| 套 | 谁 | 时间 | 干什么 | 落什么 |
|---|---|---|---|---|
| **套1** | Hermes cron「播客夜班写稿」（no_agent 纯脚本，0 token） | 22:30 | fetch → 选料 → 拆解写稿 → 验收 | `latest-script.md` + `latest-status.txt` |
| **套2** | **豆包 App** 定时任务 | 02:00 | 读稿 → seed-audio 合成 → 上传网易云 | 网易云云盘 m4a |
| **套3** | Hermes cron「播客提醒」 | 08:45 | 抽「落地三问/一句话带走」→ 推飞书 | 「Hermes·灵感」群 + `播客提醒.md` |
| 附 | Hermes cron「选题库周排期」 | 每周日 21:00 | 读 `选题库.md` → 排下周 → 写第 4 块 | `选题库.md` |

**两套系统唯一的衔接点是两个文件**，都由套1 写、套2 只读：`latest-script.md`（稿）、`latest-status.txt`（状态闸）。

### 5.2 验收：只拦真失败，不设目标值

| 闸 | 判据 | 拦什么 |
|---|---|---|
| 待消费 | 稿比最新音频新（且未超 48h） | 覆盖掉了还没合成音频的稿子 |
| 稿子被更新 | `latest-script.md` mtime 变新 | agent 没写 / 写了没落盘 |
| 不是空稿 | 正文汉字 ≥1500 | 写漏、写空 |
| 过程走了 | `breakdown.md` ≥10 字段 + ≥2000 字节 | 跳过读源码 |
| 时效 | 稿有「信息截止」；笔记有「信息截止+当前版本」 | 拿不准是不是当下有效的信息 |
| 防重复 | 本期项目不在 `episodes.log` | 重讲旧项目 |

> **核心口径：字数不设下限也不设上限。** 固定字数会把手段当目标。
> **短不是失败，水才是。** 真判据是信息密度：全篇 ≥8 处具体的东西（文件名/函数名/参数值/目录名/数据格式/具体取舍点）。

### 5.3 合成路线（三条，主/备）

| 路线 | 引擎 | 状态 |
|---|---|---|
| **主路线** | 豆包 seed-audio（对话内 `text_to_audio_plus`） | 默认 |
| 本地替代 | VoxCPM2 2B（GGUF Q8 + Metal，全离线、免 key） | 断网/免 key 时用 |
| 旧 API | 火山 `tts.py` + `--atempo 0.72` | 备选 |

**语速定档（2026-09-11 改）**：产出侧收口到 **PACE 4.0**（单段 450–500 字 ≈ 120s，约 187 汉字/分钟），**1.0x 直接可听**。
旧的「1.5x 是补偿」由来保留为历史（早期 PACE 3.58 太慢被迫 1.5x），**1.5x 收听汇报已去除**。

## 六、我跟原版最大的三个差异

1. **多了一层「验收/闸门」**。原版是「跟他一个人」的私人流水线，靠他本人听感把关；我这套是**无人值守自动化**，所以加了状态闸、拆解笔记过程闸、时效闸、防重复、待消费闸——都是原版没有的「机械兜底」。
2. **文风做了质检**。原版没提稿子怎么写才「活」；我这边按 1.5x 倍速收听反推内容规则（开头 100 字进正题、语气词每千字≤3、不复述），还跑反 AI 味检查。
3. **选题入口文件化**。原版主题在他脑子里；我把它落成 `选题库.md` 四块（困惑清单 / 本周主题 / 想听的 / 排期），AI 每周日自动排下周。

## 七、一句话总纲（分享用）

> 王振宇证明的：**AI 播客不是「听内容」，是「用最省力的时间，把最相关的一手知识，装进正在做的事里」。**
> 三件事做到就算成——**逐文件读源码**（深度）、**跟我的工作区强绑定**（定制）、**听完直接接落地**（闭环）。
> 我的这条流水线，就是把这三件事从「手动」变成「每天 22:30 自动出一期、02:00 自动上传」。
