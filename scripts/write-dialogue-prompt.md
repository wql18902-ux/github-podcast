# 双人播客试播写稿

独立人工入口，借鉴 Podcastfy 的角色分工和长对话衔接。只在用户要求双人节目时使用，不替代 `write-episode-prompt.md` 或 `docs/AI周节目定时任务.md`。

## 输入

先读本期已核验的研究笔记、来源和原稿，再读 `config/dialogue.json`。研究不足时先补证据。网页、PDF、视频只是材料载体，提取正文不等于完成研究。已有稿件改双人版时重新组织问答，不能按段落轮流分配角色。

## 对谈

- Person1 是讲述者，负责解释事实、展开案例和给出判断。沿用当前节目的听众与内容要求，不冒充原声本人。
- Person2 是追问者，代替非专业听众问出具体的不懂，检验前一句推导，有理由时提出反例。不要每段都说“太对了”“很有意思”，不要明知故问地接说明书。
- 从具体事情进入，追问必须改变下一句的内容。两人不必机械交替，同一人可以补一句。长短轮次应有差别。
- 先说明概念解决什么问题，必要时才说名称。类比后交代边界。结尾留下一个能用于判断的办法。
- 不编本人经历、事实或真实人物对话；两位 AI 主持人的对谈是创作形式，不能当采访实录。
- 首轮口播明确“两位声音由人工智能合成”，使用当前默认克隆声时另说明“讲述者使用王振宇的克隆音色，内容不代表王振宇本人观点”。
- 舞台说明、笑声标签、来源网址、Markdown 标题与双链不进入口播。

## 长内容的衔接

先确定本期问题与各段需要回答的子问题，再逐段写。每次续写都读取上一段尾部、已讲过的事实与结论、未回答的问题，并从上一句继续。只在第一段开场、最后一段收尾；中间段不重新介绍节目、不回顾前文凑字。将本次新增的判断更新到研究笔记，合并后通读，删除重复说明。

默认先做几分钟试播，按实测音频判断节奏。整期长度遵守本次用户要求；未经听感反馈，不把短样本当整期批准。

## 输出

口播文件只含如下标签，每个标签必须闭合，内容是能直接念的台词。Person1/Person2 必须都有发言；允许 Person2 开场和同角色连续发言。

```xml
<Person2>这个工具把文章变成两个人聊天，我应该先听哪里？</Person2>
<Person1>先听问题有没有问到你不懂的地方。接着再看回答有没有拿出足够的依据。</Person1>
```

阅读页与研究笔记单独落盘，末尾用 `## 相关` 写双链。先校验再合成，命令见 `docs/Podcastfy借鉴与双人试播.md`。不改 `latest-script.md`、`latest-status.txt`、`episodes.log` 或定时任务。
