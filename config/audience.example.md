# 听众画像 —— 写稿的唯一真相源

> 这份文件决定播客**讲给谁听**。
> 写稿 prompt 里每一次「落回听众的现实约束」「这事跟他有什么关系」，读的都是这里，
> 不是 prompt 里写死的某个人。**换听众 = 改这一个文件，不用改任何脚本、任何 prompt。**
>
> 填法：把「我的画像」一节填成你自己（或你心目中那一个具体听众）。下面是**填好的示例**，
> 标注「示例」的整段可以删掉。**示例人设不是作者本人，抄结构别抄内容。**

## 写稿时怎么用这份文件

固定五步，缺一步稿子就会飘：

1. **用「你」称呼**，假定听众就是画像里的人，不是「广大读者」
2. **每个项目讲完必须有一句「这事跟你的 X 有什么关系」**——X 从「现在的主线」里取
3. **类比只能从听众熟悉的东西里取**（他的日常、工具、场所、干过的事）。他要是不熟悉的领域，
   宁可多花两句解释，也别用一个他也不懂的类比
4. **不假设专业前置知识**，除非画像「已经会的」里写了
5. **画像里没有的信息不许编**。缺了就空着，稿子主动避开那个话题，别硬接

## 示例：填好之后长什么样

> 以下是一份填好的样子。**这是虚构的示例人设，不是作者本人。**

### 基本信息
- 23 岁，产品经理，白天开会晚上才有自己的时间
- 公司 + 通勤地铁 + 家里书房
- 能听的时段：早高峰地铁 40 分钟、晚上跑前热身 10 分钟、睡前 20 分钟

### 设备与技术条件
- 主力设备：MacBook Air M2 16G，没有独显
- 跑不动：本地跑不了 7B 以上的模型；公司网访问不了 GitHub _raw_ 域名
- 付费意愿：愿意为一两个真用得上的工具付月费，不愿意预付年费

### 现在的主线
1. 三个月内要把团队的周报从手工整理改成半自动
2. 想在年底前做出一个能演示的内部小工具，作为晋升材料
3. 在学 Python，卡在「看教程懂、自己写就废」

### 已经会的
- Excel 函数和透视表、基础 SQL、能看懂 JSON

### 不懂但想懂的
- Agent 到底能干什么、干不了什么
- 怎么判断一个开源项目能不能放心用

### 熟悉的生活（类比只能从这里取）
- 地铁通勤、健身房、周末做饭、带实习生、开会

### 明确的避雷
- 纯算法论文推导（听不懂也没处用）
- 需要自己训模型的方案（没卡没时间）
- 一切要他先学三个新框架才能开始的方案

### 语气与红线
- 结论先行，别铺垫
- 不许说「很简单」「一看就懂」——他试过，没那么简单
- 可以直说「这个方案不适合你」，比硬讲完更有用
